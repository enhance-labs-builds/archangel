Steiger is the linter of Feature-Sliced Design. Archangel's `fsd` preset has a rule for each of
Steiger's 21 rules, with the same name and a link to Steiger's page for it. A test in the archangel
repository runs Steiger and the preset on the same repositories, and compares the files that each
one reports.

[Feature-Sliced Design](/archangel/guides/feature-sliced-design/) tells you how to use the preset.
This page tells you how to move from Steiger.

## The config after

<Example fixture="from-steiger" file="archangel.config.ts" />

| Steiger | archangel |
| --- | --- |
| `...fsd.configs.recommended` | `extends: [fsd({ root: 'src' })]` |
| All rules on | `fsd({ root: 'src', strict: true })` |
| `'fsd/<rule>': 'off'` | `off: ['fsd/<rule>']` |
| `'fsd/<rule>': 'warn'` | No equivalent. A rule is on or off. |
| `ignores: [...]` | `ignore: [...]` in the config, in `.gitignore` syntax. It removes the files from the whole check. |
| `files: [...]` with a rule `off` | Write a rule with the same name as the preset rule. Your rule replaces it. |
| A second FSD root | A second `fsd({ root, name })` with its own `name`, for example `fsd-admin`. |

## The rules

are on by default. `strict: true` adds the four rules that Steiger has as options.

The rules about imports and folders are built-in conditions of archangel. The seven rules about
names and counts, from `typo-in-layer-name` to `shared-lib-grouping`, are conditions of the preset's
plugin, and they read the whole tree as Steiger does.

## Results that change

These differences are on purpose. The test that compares the two tools names each one.

- **A slice is any folder in a sliced layer.** The built-in rules take each folder directly in
  Entities, Features, Widgets or Pages as a slice, with or without segments. They do not know slice
  groups. Steiger finds a slice by the segments inside it. The plugin rules find slices and slice
  groups as Steiger does.
- **Each folder in `shared/ui` and `shared/lib` needs an index file.** `fsd/public-api` asks for it
  even when the segment has an index file of its own. Steiger checks those folders only when the
  segment has none.
- **A misspelt layer is reported beside the real one.** `fsd/typo-in-layer-name` reports
  `src/featurez` even when `src/features` exists. Steiger then reports nothing.
- **A layer has its exact name.** The built-in rules take only a folder named exactly as a layer.
  Steiger also reads `1_shared` or `_app` as a layer.
- **Code outside the layers is checked too.** `fsd/no-public-api-sidestep` checks imports from
  files outside the layers, such as tests. A deep import from a test is still a sidestep. Steiger
  reads only the files in the layers.
- **A re-export is an import.** Each rule counts `export ... from` as an import, because a
  re-export loads the module.

<Aside type="tip" title="One tool for more rules">
  Steiger checks Feature-Sliced Design only. With archangel, you can add your own tables and rules
  next to the preset, in the same config, and check them in one run.
</Aside>
